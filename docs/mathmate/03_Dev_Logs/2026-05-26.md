## Phase T5: Interactive Extensions (same day)

### What was built

**D5.1 — Plotly visualizations** (`FunctionGraph.tsx`, `VizRenderer.tsx`):
- Lazy-loaded Plotly (4.6MB chunk, only loaded when a viz is rendered)
- Supports `sin`, `cos`, `tan`, `sqrt`, `abs`, `log`, `exp`, `^`, `pi`, `e`
- Safe expression evaluation via `Function` constructor with strict mode
- Themed: respects light/dark CSS variables
- Hover labels, responsive layout
- Code splitting via Vite `manualChunks` for Plotly

**D5.2 — Model visualization tags** (`interactiveSegments.ts`):
- `extractInteractiveSegments()` parses `<mathmate-viz>` and `<mathmate-quiz>` tags from markdown text
- ChatMessage updated to render segments: HTML markdown, Viz components, and Quiz components can all appear in a single message
- System prompt injection teaches the model about the tags

**D5.4 — Quiz cards** (`MultipleChoice.tsx`, `FreeResponse.tsx`, `ProgressiveHint.tsx`, `QuizRenderer.tsx`):
- Multiple choice: click-to-answer with correct/incorrect colored feedback
- Free response: type input, submit to check against expected answer with fuzzy math matching
- Progressive hint: staged reveal one hint at a time, then show solution
- All themed via CSS variables

**System prompt injection**:
- Combined system instructions (user's custom prompt + viz/quiz tag documentation) prepended as a system message before every conversation
- Models learn to emit `<mathmate-viz>` and `<mathmate-quiz>` tags naturally

### Lessons learned
1. **Plotly is huge (4.6MB)** but lazy-loading via dynamic `import()` works perfectly — it's only loaded when a `<FunctionGraph>` mounts
2. **Interactive segments** are a cleaner approach than post-processing rendered HTML — splitting markdown on custom tags before rendering avoids fragile DOM parsing
3. **System prompt injection** is the simplest way to teach the model new capabilities — no function definitions, no tool loops, no special parsing
4. **Fuzzy math matching** for free-response quizzes uses numeric evaluation fallback — `sin(pi/6)` and `0.5` both match `1/2`
5. **CSS variables** continue to pay off — all new viz and quiz components use `var(--color-*)` and work in dark mode without any dark-mode-specific code

## Lessons learned (initial phases)
1. **Modular Rust modules** pay off — adding 6 new modules (project, vault, images, memory, wrapup, textbook) was straightforward because each has clear responsibilities and zero internal coupling
2. **Zustand stores per domain** kept the frontend manageable — chatStore, projectStore, vaultStore, memoryStore, configStore never needed cross-store dependencies
3. **The LaTeX snippet catalog** was trivial to port from JSON to TypeScript; 75 snippet definitions in ~200 lines
4. **CSS variables from day zero** made dark mode automatic across 28 components — no dark-mode-specific styling needed
5. **30 Tauri commands** is a lot — consider merging related commands into single endpoints with action enums for Phase T4

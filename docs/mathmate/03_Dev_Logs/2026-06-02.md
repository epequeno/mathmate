# Dev Log — 2026-06-02

## Phase 13A — Synapse MCP Subprocess Client

Implemented the MCP subprocess client that connects MathMate to the Synapse knowledge base, replacing hand-rolled vault tools with a managed stdio MCP protocol subprocess.

### 13A-E1 — `mcp_client.rs` (new module)
- **`McpClient` struct** — manages a `synapse mcp start --vault <path>` child process with `BufReader`/`BufWriter` on stdin/stdout
- **MCP handshake** — sends `initialize` request with protocol version `2024-11-05`, handles response, then sends `notifications/initialized`
- **`call(tool, args)`** — sends JSON-RPC `tools/call` request, reads response lines until matching ID (skips non-matching messages/log lines), 10s timeout
- **`list_tools()`** — fetches tool list via `tools/list`, converts MCP tool definitions to MathMate's `ToolDefinition` format (OpenAI-compatible)
- **`stop()`** — kills child process and waits for exit
- **`resolve_synapse_binary()`** — priority chain: `SYNAPSE_BIN` env var → `~/.cargo/bin/synapse` → `<workspace>/../synapse/target/release/synapse` (dev sibling)
- **`is_synapse_available()`** — boolean check without spawning
- 3 unit tests + 1 integration test (`#[ignore]`)

### 13A-E2 — `lib.rs` integration
- Added `mcp_client: Mutex<Option<McpClient>>` to `AppState` (initialized `None`)
- **`get_tool_definitions(state)`** — now returns Synapse tools (via `list_tools`) when MCP client is running; falls back to old vault tools when offline
- **`execute_tool(state, call_id, tool_name, arguments, project_id)`** — routes `note_*` and `vault_info` tools through `McpClient::call()`; falls back to legacy `tools::execute_tool` for `calculate`/`graph`/old vault tools
- New Tauri commands:
  - `start_synapse_mcp` — spawns Synapse MCP for a given vault path
  - `stop_synapse_mcp` — kills the running MCP subprocess
  - `synapse_mcp_status` — returns `{ running, tool_count }`
  - `check_synapse_available` — returns boolean

### 13A-E3 — Frontend integration
- **`projectStore.ts`** — added `synapseStatus: { running, vault_path, tool_count }`, plus `startSynapse()`, `stopSynapse()`, `checkSynapseStatus()` methods
- **Auto-start on project switch** — `setCurrentProject` stops Synapse for the old project, starts it for the new project if it has a `vault_path`
- **Auto-start on load** — when the first project is auto-selected, Synapse starts if the project has a vault
- **`VaultPage.tsx`** — Synapse status indicator in toolbar (green dot + "Synapse" when active, amber dot + "Legacy" when falling back to old tools)

## Phase 13B — Vault UI Redesign

Replaced VaultPage's legacy `scan_vault` / `read_note` approach with Synapse API calls via the `synapse_call` proxy command, and added full UI capabilities: FTS search, folder-grouped note list, edit mode, new note creation, and backlinks panel.

### 13B-E1 — `synapse_call` Tauri command
- Added `synapse_call(tool, args)` in `lib.rs` — thin proxy command that calls through to `McpClient::call(&tool, args)`
- Registered in the Tauri invoke handler

### 13B-E2 — `vaultStore.ts` rewrite
- Replaced `scanVault` / `readNote` with Synapse-backed calls:
  - **`loadNotes()`** — calls `note_list`, falls back to `scan_vault` when offline
  - **`searchNotes(q)`** — calls `note_search` (FTS), fallback to filename matching on legacy
  - **`readNote(path)`** — calls `note_read`, returns `{ path, title, body }`
  - **`saveNote(path, content, title?)`** — calls `note_update`
  - **`createNote(title, content)`** — calls `note_create`, reloads note list
  - **`loadBacklinks(path)`** — calls `note_backlinks`, returns `{ backlinks, forward_links }`
- Added `checkSynapseStatus()` — queries `vault_info` for note count
- New state: `searchResults`, `searchQuery`, `backlinks`, `synapseRunning`, `noteCount`
- All Synapse calls go through `invoke("synapse_call", { tool, args })`
- Legacy `scan_vault` kept as fallback when Synapse not running

### 13B-E3 — `VaultPage.tsx` redesign
- **Search bar** — FTS search with 300ms debounce; shows snippets from `note_search`; clearable
- **Folder-grouped note list** — groups by parent folder, root folder first, sorted alphabetically
- **Preview / Edit mode** — toggled by `[Edit]` button:
  - Preview: rendered markdown (KaTeX + sanitized) or raw view toggle
  - Edit: `<textarea>` with raw body, `[Save]` → `note_update`, `[Cancel]` to revert
  - Unsaved changes indicator + save confirmation
- **Backlinks panel** — collapsible section showing backlinks and forward links with broken-link detection
- **New note button** — `[+ New note]` at bottom of list; inline form asks for title, then calls `note_create`
- **Synapse not running banner** — amber warning bar with `[Start Synapse]` button; content falls back to legacy `scan_vault`
- **Toolbar** — Synapse status shows active note count (e.g. "Synapse active (12 notes)")
- **Error states** — inline save error below editor with dismiss; note-level error in title bar

## Phase 13C — Context Panel & Chat Integration

Added three vault-aware features to the chat flow: Related Notes in the context panel, note citation chips on assistant messages, and a Quick Save button.

### 13C-E1 — Related Notes (ContextPanel)
- Added "Related Notes" section in ContextPanel (slotted between Token Breakdown and Tool Calls)
- Extracts combined text from the last 3 user messages (truncated to 200 chars)
- Fires `note_search` via `synapse_call` with 1500ms debounce
- Shows up to 5 clickable note titles; clicking navigates to `/vault` and selects the note via `navigateToNote`
- Hidden entirely when synapse is not running

### 13C-E2 — Note Citation chips (ChatMessage)
- New `VaultChips` component renders below assistant messages
- Scans tool_result segments for Synapse write operations (`note_create`, `note_update`)
- Renders a small chip for each result: `[📄 Note title →]`
- Clicking the chip calls `navigateToNote(path)` + navigates to `/vault`
- Chips shown for both segment-based (timeline) and legacy rendering

### 13C-E3 — Quick Save button (ChatMessage)
- `[🔖 Save to vault]` button appears on hover over any assistant message with text content (only when Synapse running)
- Clicking opens a popover with pre-filled title: "<session title> — <date>"
- Calls `note_create` via vaultStore.saveNote and shows a green confirmation "Saved to vault" chip
- Hidden during streaming

### 13C-E4 — Navigation helper (vaultStore)
- Added `pendingSelectPath: string | null` + `navigateToNote(path)` to vaultStore
- VaultPage watches `pendingSelectPath` in a useEffect; when non-null, selects and reads the note, then clears it
- Used by both Related Notes and citation chips to switch to the Vault tab and select the right note

## Hardening — Streaming, Tool Loop, Vault Scope

Implemented follow-up hardening from the app assessment while intentionally leaving native Anthropic support, custom provider env-key support, and Plotly code-splitting for later work.

### Changes
- **Streaming parser:** Normalizes string/object/array content and reasoning deltas before rendering; preserves all tool-call deltas when a provider emits multiple `delta.tool_calls` in one chunk.
- **Tool loop guardrail:** Persists the latest session after tool-result messages and writes an explicit assistant notice if max tool rounds are exhausted without a final model answer.
- **Vault command scope:** `scan_vault` and `read_note` now normalize paths and enforce active-project allowed roots before reading the filesystem.
- **External open confirmation:** Vault/textbook open actions now attempt scoped open first and only pass `confirmed=true` after a user warning dialog.
- **Sanitizer policy:** Removed form/interactive tags and SVG `foreignObject` from sanitized markdown output.

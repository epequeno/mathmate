## Phase E — Item 2: Snapshot Pipeline Hardening ✅

### Bugs Fixed

**Bug 1: `requestSnapshot` ignored `htmlContent` parameter**
- `SnapshotStore.requestSnapshot` was building an empty KaTeX shell and passing it to `LaTeXSnapshotPool.snapshot(html:)` — the per-unit content was computed but **never rendered**.
- **Fix**: Changed the pool from single-phase `snapshot(html:)` to two-phase `snapshot(shellHTML:contentHTML:)`:
  1. Load the KaTeX shell HTML (CSS + JS + `updateContent()` function)
  2. Wait for the initial height callback (shell now posts scroll height on load)
  3. Inject actual content via `evaluateJavaScript("updateContent(\"...\")")`
  4. Wait for the re-render height callback
  5. Capture the image

**Bug 2: `loadAndWait` ignored `timeout` parameter**
- `PooledWebView.loadAndWait(html:timeout:)` accepted a `timeout` parameter but never used it — it called `withCheckedContinuation` with no timeout enforcement, making it hang forever if the JS callback never fired.
- **Fix**: Both `loadShellAndWait` and `injectContentAndWait` now schedule a `DispatchQueue.main.asyncAfter` that resumes the continuation with `false` if the timeout fires first. `didResume` guards ensure exactly-once semantics (

**Bug 3: Silent failures → stuck `.loading`**
- If the pool returned `nil` (failure), the state stayed `.loading` indefinitely.
- **Fix**: Already handled — the existing `guard let image = ... else { states[unitId] = .failed; return }` transitions to `.failed`. Verified this path is correct.

**Shell HTML: missing initial height post**
- The KaTeX shell only fired `heightUpdate` inside the `updateContent()` JS function. On initial load without calling `updateContent`, no message was posted — the old code happened to work only by coincidence.
- **Fix**: Added `window.webkit.messageHandlers.heightUpdate.postMessage(document.body.scrollHeight);` at the bottom of the shell script, so the initial load always completes.

## Phase E — Item 4: Session Persistence Scalability ✅

### Changes
All in `prototype/MathMate/Sources/MathMate/Persistence/SessionStore.swift`

**1. `loadHeader` — streaming read**
- Before: `String(contentsOf:)` loaded entire JSONL file into memory, then `components(separatedBy:)` split it, then took `.first`
- After: `FileHandle(forReadingFrom:)` reads just the first 4KB, finds the first newline byte, decodes header from that slice
- Memory: O(size of file) → O(header size)

**2. `countMessages` — newline streaming**
- Before: loaded entire file, split into array, filtered empty lines, subtracted 1
- After: streams 64KB chunks through `FileHandle`, counts newline bytes, subtracts 1 for header
- Memory: O(size of file) → O(64KB)

**3. `updateHeader` — data-level rewrite**
- Before: `String(contentsOf:)` loaded file, `components(separatedBy:)` split, modified lines[0], re-joined, rewrote
- After: locates first newline offset via streaming (`firstIndex(of:)` on Data), seeks past it, reads rest as Data, constructs new file as `headerLine + restData`, writes atomically
- Memory: O(size of file as String) → O(rest of file as Data)

**4. `loadMessages` — streaming line-by-line parsing**
- Before: loaded entire file, `components(separatedBy:)` split into huge String array, `dropFirst()` discarded header, `compactMap` decoded each
- After: streams 64KB chunks, processes complete lines from buffer incrementally, decodes as Data directly without String round-trip, reserves 128 capacity
- Memory: O(size of file) → O(chunk size + one line)

## Phase B MB1 — Runtime Retrieval Hook (Completed)

The memory context now gets injected into every model call in `sendMessage()`.

**Flow:**
1. User sends a message
2. `_topicHints(from:)` extracts search query from the user message (first ~200 chars)
3. If `memoryEnabled`, calls `memoryEngine.retrieveRelevantMemory(query:limit:)`
4. `memoryEngine.buildMemoryContextBlock(from:)` formats scored items as a compact block
5. Block is inserted in the prompt stack: `[system] + [memory context] + [message history]`
6. Model sees the memory context alongside the system prompt

**Settings (UserDefaults-backed):**
- `memoryEnabled: Bool` — global toggle for memory injection (default: true)
- `maxMemoryItems: Int` — max items injected per turn (default: 6, range: 1-20)

Injection is silent — no visible changes to the user's message list. The memory block appears only in the API call to the model.

## Phase C — Flag-Based Intelligence (Complete)

### What changed

**C2 — Flag-weighted memory extraction (`ViewModels/MemoryViewModel.swift`):**
- `extractFromSession()` now extracts **both** top-level flagged messages AND individual flagged units.
- Each flagged unit becomes its own `MemoryItem` with content prefixed by `[<unitType>]` for richer retrieval weighting.
- Flagged unit items get slightly higher confidence (0.85 vs 0.80) since they're more granular signals.
- Unit type prefix enables the MemoryEngine to weight retrievals by category (e.g., explanation > thinking).

**C3 — Flag-preserving compaction (`ViewModels/ChatViewModel.swift`):**
- `_serializeForCompaction()`: Flagged units now use `[FLAGGED UNIT: <type> | <label>] ⭐ PRESERVE VERBATIM ⭐` markers with explicit `[END FLAGGED UNIT]` delimiters. User-flagged messages use matching `[FLAGGED USER MESSAGE]` markers.
- `_generateCompactionSummary()`: Prompt now includes explicit "⚠️ FLAG-PRESERVATION RULE" directive telling the LLM to preserve flagged content verbatim and include it under a dedicated "Flagged Content (verbatim)" section.
- `_fallbackCompactionSummary()`: Added `## Flagged Content (verbatim)` section that lists all flagged units from compacted messages when the LLM is unavailable.

**C4 — Wrap-up integration (`ViewModels/ChatViewModel.swift`):**
- `_buildWrapUpPrompt()`: Flagged content section now includes `⚠️ FLAG PRESERVATION RULE` directive with explicit instructions to represent flagged segments accurately and prominently.
- Added `★ Flagged Highlights` section to the wrap-up template, positioned after "Important Formulas" so it gets visual prominence in generated study notes.
- Flagged unit headers now include both type and label: `[FLAGGED: <type> | <label>]`.

**C5 — `/flags` command upgrade (`ViewModels/ChatViewModel.swift`):**
- Now shows per-unit flags grouped by message with tree-style indentation.
- Each flagged unit displays its type and label: `★ [<type> | <label>] <preview>`.
- Supports optional `type:<type>` filter: e.g., `/flags type:explanation`, `/flags type:quizCard`.
- Lists available unit types at the bottom for discoverability.
- Shows total count including both top-level flagged messages and flagged units.

### Why this matters

1. **Flags drive intelligence**: Per-unit flags are no longer just UI decorations — they actively influence memory extraction quality, compaction fidelity, and wrap-up completeness.
2. **No data loss on compaction**: Flagged content survives context window pressure via explicit preservation directives in both the serialized format and the LLM prompt.
3. **Discoverable flag management**: The upgraded `/flags` command lets users audit what they've flagged and filter by type.
4. **Better study notes**: The `★ Flagged Highlights` section ensures important concepts appear prominently in exported Obsidian study logs.

### Files modified

**`Models/ModelProvider.swift`**:
- `ImageAttachment.Source` extended with `.disk(sessionId:imageId:filename)` variant

**`Rendering/LaTeXView.swift`**: (no changes) — LaTeXView continues to use live WKWebView during streaming

**`Views/MainView.swift`**:
- `MessageRow`: added `@ObservedObject var snapshotStore`; replaced `LaTeXView` text rendering with `textUnitContent` helper that switches to `SnapshotView` when snapshot is available
- `textUnitContent(unitId:isStreaming:)`: renders `SnapshotView` for completed units, falls back to `LaTeXView` during streaming
- `ImageMessageView`, `ImageThumbnail`, `FullSizeImageSheet`: updated `loadImage()` to use `ImageDiskCache` (cache first, then base64 fallback)

**`Views/WidgetView.swift`**:
- `WidgetView`: extracted legacy widget path to `LegacyWidgetContent`
- `LegacyWidgetContent`: checks `LegacyWidgetCap.canRenderLive()`; shows live `WidgetWebView` or snapshot placeholder

**`ViewModels/ChatViewModel.swift`**:
- `_requestSnapshots(for:)`: new method called when streaming ends — requests snapshots for all text units + migrates images to disk cache
- `currentSession.didSet`: resets `SnapshotStore` and `LegacyWidgetCap` on session change
- `clearChat()`: resets snapshot store and widget cap

### Why this architecture

1. **Streaming-first**: During active streaming, each message keeps its own `LaTeXView` with a live WKWebView for real-time updates. Snapshots are requested only after `isStreaming = false`.

2. **Pixel-perfect parity**: `LaTeXShellHTML` is identical to the HTML used by `LaTeXView`, so captured snapshots match the live rendering exactly.

3. **Pool reuse**: 2 pooled WKWebViews handle all snapshot requests. WebKit processes are reused across messages rather than created per-message.

4. **Widget cap is pragmatic**: Rather than snapshotting complex JSXGraph content, the cap limits live instances to 1. Interactive widgets remain functional within the cap.

5. **Disk cache is transparent**: `ImageMessageView` and friends call `ImageDiskCache.loadNSImage()` which checks NSCache first, then disk, then falls back to base64. The UI never knows where the image came from.

## THQ-2 — Fix `flags` Type Mismatch (Thinking Trace Data Loss)

### Problem
The thinking/reasoning trace was being stuffed into `message.flags` as a string (`flags.thinking`), but the Rust `Message` struct defined `flags: Option<HashMap<String, bool>>` — meaning boolean values only. This caused data loss: the thinking text was never serialized/deserialized correctly. On session reload, the thinking trace was gone.

### Changes
- **Rust** (`session.rs`): Added `thinking: Option<String>` field to `Message` struct with `skip_serializing_if`
- **TypeScript** (`types.ts`): Added `thinking?: string` to `Message` interface
- **chatStore.ts**: Changed `sendMessage` to write `assistantMsg.thinking = accumulatedThinking` instead of `flags`
- **ChatMessage.tsx**: Updated thinking trace display to read `message.thinking` directly, with graceful fallback to legacy `flags.thinking` for old sessions

## THQ-3 — Add HTML Sanitization (DOMPurify)

### Problem
Both `ChatMessage.tsx` and `ChatPage.tsx` use `dangerouslySetInnerHTML` with `renderMarkdown()` output. A malicious model response or compromised provider could inject arbitrary HTML including script tags, leading to XSS.

### Changes
- Installed `dompurify` and `@types/dompurify`
- Created `src/lib/sanitize.ts` with a KaTeX-safe DOMPurify configuration:
  - Allows MathML elements (math, mi, mo, mn, mfrac, msqrt, etc.)
  - Allows SVG elements and attributes (paths, transforms, viewBox, etc.)
  - Allows inline styles generated by KaTeX (color, background, etc.)
  - Forbids script, style, iframe, object, embed, form elements
  - Strips all on* event handler attributes
- Wrapped `dangerouslySetInnerHTML` in both `ChatMessage.tsx` (message bubble) and `ChatPage.tsx` (streaming footer)

## THQ-4 — Fix `_getEnvKey` — Route Env Vars Through Rust

### Problem
The `_getEnvKey` function attempted to read environment variables via `window.__TAURI__?.os?.env`, which is unreliable, non-portable, and bypasses Tauri's permission system. It also fell back to Vite `import.meta.env`, which doesn't work in production builds.

### Changes
- **Rust** (`lib.rs`): Added `get_env_var` Tauri command with an explicit whitelist of allowed env var names (`OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`). Returns an error for any unlisted key.
- Registered `get_env_var` in the invoke handler
- **TypeScript** (`providers.ts`): Rewrote `_getEnvKey` as async, using `invoke("get_env_var", { key })` as the primary path, with Vite fallback for dev mode only
- Updated all `_getEnvKey` call sites to use `await`

## Synapse — Memory Retrieval in Chat UI

### Problem
The memory/SQLite backend was complete (store, query, forget, profile), but there was no integration between the chat flow and the memory system. Memories were only accessible via the side panel ContextPanel's manual search. The AI model had no access to stored context, and users had no visibility into memory hits during a conversation.

### Changes

**chatStore.ts** — Auto-memory retrieval on each user message:
- On sendMessage, before streaming, query memories using the user's input as the search term (up to 8 results)
- Inject retrieved memories into the system prompt as a "## Retrieved context (learner memory)" block so the model can reference them
- Auto-store each user question as a memory for future recall (tagged as "chat" / "question")
- Clear retrieval indicators after the response is saved
- Added retrievedMemories, memoryEnabled, memorySearchActive state
- Added setMemoryEnabled and clearRetrievedMemories actions

**MemoryRetrievalBar.tsx** — New component:
- Collapsible inline bar showing retrieved memories during streaming
- Header shows memory count and query text
- Each memory shows icon (by source type), content excerpt (120 chars), source label, relevance score, and tags

**ChatPage.tsx** — Integrated retrieval bar:
- Renders MemoryRetrievalBar in the Virtuoso Footer when streaming and memories were retrieved
- Passes retrievedMemories and inputText to the bar

## THQ-7 — Fix Retry Logic: Don't Retry Aborted Requests

**Problem**: `AbortError` (user pressing Cancel) was classified as retryable, causing the app to attempt re-stream after a 2s delay.

**Changes**:
- Added early-exit guard before the retry gate: if `abortController.signal.aborted` or `err.name === "AbortError"`, abort handling runs immediately and the function returns
- Simplified `isRetryable` to only inspect `err instanceof StreamError ? err.retryable : false`
- Removed the now-unreachable abort-handling block inside the retry loop
- Added `StreamError` to the import from `providers.ts`

## THQ-9 — Atomic Session Writes (Prevent Corruption on Crash)

**Problem**: `write_jsonl` (used by `save_session` and `rename_session`) wrote directly to the target file — a crash mid-write would corrupt the session.

**Changes**:
- `write_jsonl` now writes to a `.jsonl.tmp` file, then atomically renames (POSIX atomic rename) to the target path
- Added `cleanup_stale_tmp()` that removes orphaned `.jsonl.tmp` files left by previous crashes
- `sessions_dir()` now calls `cleanup_stale_tmp()` after `create_dir_all`

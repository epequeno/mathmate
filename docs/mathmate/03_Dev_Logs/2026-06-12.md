Performed a full critical review of the `mathmate-v2/` codebase (~27,500 LOC across 92 files: ~20K TS/TSX frontend, ~7.3K Rust backend). Findings consolidated into **Phase 14: Architectural Hardening** in the roadmap, with 8 sub-phases and 9 implementation plan documents.

### Key findings (grouped by severity)

**High-leverage (block future velocity):**
- `chatStore.sendMessage` is ~470 lines mixing 11 concerns (slash routing, session mgmt, memory retrieval, prompt assembly, vision check, tool loop, segment accumulation, auto-store, retry, abort, error rendering). No tests.
- The frontend makes at least 25 `invoke<T>(...)` calls (exact count should be generated, not hand-counted) with hand-written argument names silently coerced to snake_case. No compile-time contract check.
- `lib.rs` is 1015 lines of `#[tauri::command]` routing; the path-scope guard is reimplemented four different ways inline.
- The MCP client holds a `Mutex<Option<McpClient>>` across blocking `BufReader.read_line` calls; the Synapse/legacy fallback is checked in 9 separate store actions.
- Streaming state is 8 loosely-coupled Zustand fields; race condition mid-tool-round can briefly show an empty assistant message.

**Medium (correctness / robustness):**
- `wrapup.rs:178` has a real TODO: `let session_id = "unknown"` is silently producing corrupt study logs.
- `session::append_message` can lose data on crash (in-memory update succeeds; disk write may fail).
- `assembleToolCalls` silently swallows malformed tool-call arguments.
- `pathscope.rs` has 6+ tests with commented-out assertions — green tests that lie.
- `open_path` has a `confirmed: Option<bool>` parameter with policy-sensitive semantics; frontend call-sites currently pass `confirmed` after a user confirmation dialog. This is not dead API surface and needs an explicit keep/remove decision.
- `_toolCallDeltas` field in `chatStore` is written but never read.
- The two memory-safety implementations (TS `memorySafety.ts` + Rust `memory.rs`) are parallel code paths with no shared source.

**Low-hanging (no behavior change):**
- Dynamic `await import("@tauri-apps/api/...")` in `App.tsx` and `chatStore.ts` is unnecessary defensive code.
- `Layout.tsx` mount-once effect lacks a `useRef` guard; will create phantom sessions if Layout ever unmounts.
- The `synapse_tools` string array in `execute_tool` duplicates `mcp_client.list_tools()`.
- `visionFilterEnabled` flag in `configStore` is set but never read.
- `streamedText` / `streamedThinking` have no upper bound (pathological model could OOM).
- `Sidebar.tsx` (810 lines), `ChatMessage.tsx` (619), `ProjectSettingsPanel.tsx` (751), `PdfViewer.tsx` (903) are god-components with massive inline-style objects.
- Anthropic provider is string-matched but the parser reads OpenAI shape — it doesn't actually work today.

## Phase 15B: Discriminated-Union Stream State

Replaced 8 parallel Zustand fields (`streaming`, `abortController`, `streamedText`, `streamedThinking`, `streamingContent`, `streamingThinking`, `streamSegments`, `error`) with a single `phase: TurnPhase` discriminated union.

### TurnPhase discriminated union (`src/lib/turn/phase.ts`)

| Variant | When | Key fields |
|---------|------|------------|
| `idle` | No turn in progress | — |
| `preparing` | `sendMessage` accepted, pre-stream | `sessionId`, `capturedInput` |
| `streaming` | Orchestrator yielding deltas | `sessionId`, `round`, `streamSegments`, `abortController` |
| `finishing` | `turn-finished` emitted | `sessionId`, `streamSegments` |
| `aborted` | User cancelled / `AbortError` | `sessionId`, `partialSegments`, `partialText`, `partialThinking` |
| `errored` | Non-retryable error | `sessionId`, `partialSegments`, `error: AppError` |

Transition map: `idle → preparing → streaming → finishing → idle`, with `streaming → aborted → idle` and `streaming → errored → idle` side paths.

### Selectors (all exported from `phase.ts`)

- `isTurnActive(phase)` — true for `preparing | streaming | finishing`
- `isStreaming(phase)` — true for `streaming` only
- `isAborted(phase)` / `isTurnErrored(phase)` — terminal state checks
- `latestText(phase)` — derive from segments (streaming/finishing) or stored partial (aborted)
- `latestThinking(phase)` — derive from thinking segments or stored partial
- `currentSegments(phase)` — current segments from the active variant
- `currentAbortController(phase)` — `AbortController` only from `streaming`
- `currentTurnError(phase)` — `AppError` only from `errored`

### Store changes (`chatStore.ts`)

- Removed from `ChatState` interface: `streaming`, `abortController`, `streamedText`, `streamedThinking`, `streamingContent`, `streamingThinking`, `streamSegments`, `error`
- Added: `phase: TurnPhase`, `capturedInput: string`
- `streamedText`/`streamedThinking`/`streamSegments` kept as top-level convenience fields (Zustand subscriptions), populated during `streaming` phase
- `sendMessage` uses `for await (const event of runTurn(...))` with phase transitions in the event switch
- Retry loop: on retryable error, transitions to `preparing` (not idle) so `isTurnActive` returns true
- Abort: saves partial message to session, transitions to `aborted` with partial text/thinking/segments
- Error: saves error message to session, transitions to `errored`
- `clearError`: resets to `IDLE`
- `cancelStream`: reads `AbortController` from `phase` via `currentAbortController()`

### Consumer updates

| File | Change |
|------|--------|
| `ChatInput.tsx` | `streaming` → `phase.kind === "streaming"`; `isTurnActive(phase)` for send guard |
| `ChatPage.tsx` | Derives `streaming`/`error`/`streamingContent`/`streamingThinking` from `phase` + selector fields |
| `useKeyboardShortcuts.ts` | `store.streaming` → `isStreaming(store.phase)` |

## Phase 15C: Anthropic Wire-Protocol Support

Added native Anthropic streaming support end-to-end (request format + SSE parsing) while preserving existing OpenAI/OpenRouter behavior.

### Wire-variant routing (`detectWireVariant`)
- OpenRouter → `openai_compatible` (even for Claude models)
- Native Anthropic → `anthropic_native`
- Never infers from model ID (prevents OpenRouter Claude misrouting)

### New code paths (all in `src/lib/providers.ts`)

| Function | Role |
|----------|------|
| `detectWireVariant(provider)` | Wire variant from provider config |
| `readSSEFrames(reader)` | Robust SSE frame reader (multi-line data, events, split chunks) |
| `parseOpenAIFrame(raw)` | Extracted from `_parseDelta` — no behaviour change |
| `parseAnthropicFrame(event, data, state)` | Anthropic SSE → `StreamChunk` with stable tool-call IDs |
| `convertMessagesToAnthropicBlocks(messages)` | `MessagePayload[]` → Anthropic content blocks |
| `convertToolsToAnthropicSchema(tools)` | OpenAI `function.parameters` → Anthropic `input_schema` |

### Anthropic parser details
- Handles 10 event types: `message_start`, `content_block_start/delta/stop`, `message_delta/stop`, `ping`, `error`
- Per-index `AnthropicParseState` tracks `toolArgsByIndex`, `toolNameByIndex`, `callIdByIndex` → stable IDs across partial `input_json_delta` frames
- Emits existing `StreamChunk.tool_call_delta(s)` format → compatible with `assembleToolCalls()` unchanged
- Thinking/text/tool-use interleaving supported

### Request conversion
- System messages → Anthropic `system[]` top-level parameter
- Assistant tool calls → `tool_use` content blocks with stable IDs
- Tool results (`role: "tool"`) → user message with `tool_result` blocks
- Image parts → `{ type: "image", source: { type: "base64", ... } }`

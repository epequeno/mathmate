## Phase 12B: Tool Registry & Execution

Implemented the Rust tool registry, three v1 tool executors, and the multi-round tool loop in chatStore.

### 12B-E1 — Rust tool framework (`tools/mod.rs`)
- `ToolDefinition`, `FunctionDef` — OpenAI-compatible tool definition structs
- `ToolCall`, `ToolResult` — tool call from model + execution result
- `get_tool_definitions()` — returns all 3 tool definitions
- `execute_tool(call, vault_path)` — dispatcher with structured error handling
- 3 tests: definition count, unknown tool handling, OpenAI compatibility

### 12B-E2 — `calculate` executor (`tools/calculate.rs`)
- Uses `meval` crate for safe numeric expression evaluation
- Supports: `+ - * / ^`, trig functions (`sin`, `cos`, `tan`, `asin`, `acos`, `atan`), `ln`, `sqrt`, `abs`, `exp`, constants (`pi`, `e`)
- Guards: max 500-char expression, empty check, non-finite result handling
- Returns `{ "value": number, "expression": string }`
- 8 tests: basic arithmetic, order of operations, trig, logarithms, sqrt/abs, invalid expressions, empty, too-long

### 12B-E3 — `graph` executor (`tools/graph.rs`)
- Evaluates y=f(x) at evenly-spaced points using `meval::Expr::bind("x")`
- Configurable: xmin, xmax, steps (32–1000, default 200)
- Returns `{ "type": "function_2d", "points": [[x,y],...], "meta": {...} }`
- Filters non-finite points (discontinuities like 1/x at 0)
- 8 tests: parabola, sine wave, defaults, step clamping, invalid expr, xmin≥xmax, missing params, discontinuity filtering

### 12B-E4 — `vault_search` executor (`tools/vault_search.rs`)
- Case-insensitive keyword search across vault markdown notes
- Scoring: title match ×3, content match ×1
- Bounded: max 10 results, max 500-char snippets, max 200-char query
- Returns `{ "results": [{path, title, score, snippet, tags}], "query", "total_notes_scanned" }`
- 5 tests: missing query, empty query, no vault path, query too long, snippet extraction

### 12B-E5 — Tauri commands (`lib.rs`)
- `get_tool_definitions()` — returns OpenAI-compatible tool definitions
- `execute_tool(call_id, tool_name, arguments, project_id)` — executes tool with auto vault_path resolution from project
- Registered in invoke handler

### 12B-E6 — Provider tool payload (`providers.ts`)
- `buildToolPayload(messages, toolDefs)` — wraps messages + tool definitions
- `streamChat()` updated to accept `{ messages, tools }` payload format
- `body.tools` included when tools present

### 12B-E7 — Multi-round tool loop (`chatStore.ts`)
- `MAX_TOOL_ROUNDS = 3`, `TOOL_TIMEOUT_MS = 8000`
- Flow: stream → assemble tool calls → execute via Rust → append tool results → continue loop
- Tool call segments: `running` status during execution
- Tool result segments: success/error styling
- Protocol messages: assistant `tool_calls` + `tool` role results for next round
- Conversation history accumulated across rounds
- Timeout handling per tool call (Promise.race)

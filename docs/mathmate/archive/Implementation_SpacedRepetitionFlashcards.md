# Implementation Plan: Spaced Repetition Flashcards

## 1) Goal

Add a lightweight spaced-repetition flashcard system to MathMate.  Cards are
generated by the AI from session content or on demand via `/flashcards`.
Each card is self-graded with a 4-button rating (Again / Hard / Good / Easy),
and due dates advance using a simplified SM-2-style algorithm.  Completed
sessions feed into the mastery evaluator.

Inspired by the flashcard system in [Get It.](https://github.com/beltromatti/get-it),
adapted to MathMate's math-first content and existing memory infrastructure.

---

## 2) Scope

### In scope
- AI-generated flashcard decks from a topic string or from the current
  session's messages
- Flashcard review mode (one card at a time, flip-to-reveal, 4-button rating)
- SM-2 simplified scheduling: compute next due date from rating
- Cards persisted in a `flashcard_decks` + `flashcards` DB table
- `/flashcards [topic]` slash command to generate a deck
- "Due today" review queue surfaced on OverviewPage
- Ratings feed into memory DB mastery scores (recall signal)

### Out of scope
- Full SM-2 with `easiness factor` and interval history (use simplified
  fixed intervals for v1; upgrade in a later pass)
- Image/diagram cards (text+math only for v1)
- Cross-device sync

---

## 3) Spaced Repetition Algorithm (v1 — Simplified Fixed-Interval SM-2)

| Rating | Button | Next due (days from now) |
|---|---|---|
| 1 | Again | 0 (show again in same session) |
| 2 | Hard | 1 |
| 3 | Good | 3 |
| 4 | Easy | 7 |

After 3 consecutive "Easy" ratings: interval doubles each time (7 → 14 → 28).
Store `consecutive_easy` count per card for this.

v2 upgrade path: full SM-2 with per-card easiness factor stored in DB.

### SR1 — DB schema: flashcard tables
**Modify:** `mathmate-v2/src-tauri/src/memory.rs`

**Tasks:**
- Add to `init_schema`:
  ```sql
  CREATE TABLE IF NOT EXISTS flashcard_decks (
      id TEXT PRIMARY KEY,
      project_id TEXT,
      topic TEXT NOT NULL,
      created_at TEXT NOT NULL DEFAULT (datetime('now')),
      card_count INTEGER NOT NULL DEFAULT 0,
      source_session_id TEXT   -- optional, if generated from a session
  );

  CREATE TABLE IF NOT EXISTS flashcards (
      id TEXT PRIMARY KEY,
      deck_id TEXT NOT NULL,
      project_id TEXT,
      front TEXT NOT NULL,      -- question (may contain LaTeX)
      back TEXT NOT NULL,       -- answer (may contain LaTeX)
      rating INTEGER,           -- 1–4, last rating
      consecutive_easy INTEGER NOT NULL DEFAULT 0,
      due_at TEXT,              -- ISO8601, null = new card
      last_reviewed_at TEXT,
      created_at TEXT NOT NULL DEFAULT (datetime('now'))
  );
  ```
- Add helpers:
  - `create_deck(project_id, topic, source_session_id) -> FlashcardDeck`
  - `insert_cards(deck_id, cards: Vec<(String, String)>)`
  - `rate_card(card_id, rating: u8) -> updated Card` (applies scheduling)
  - `get_due_cards(project_id, limit: usize) -> Vec<Flashcard>`
  - `list_decks(project_id) -> Vec<FlashcardDeck>`

### SR2 — Scheduling logic
**Create:** `mathmate-v2/src-tauri/src/flashcards.rs`

**Tasks:**
- Define structs:
  ```rust
  pub struct FlashcardDeck {
      pub id: String,
      pub project_id: Option<String>,
      pub topic: String,
      pub created_at: String,
      pub card_count: usize,
      pub source_session_id: Option<String>,
  }

  pub struct Flashcard {
      pub id: String,
      pub deck_id: String,
      pub front: String,
      pub back: String,
      pub rating: Option<u8>,
      pub consecutive_easy: u32,
      pub due_at: Option<String>,
      pub last_reviewed_at: Option<String>,
  }
  ```
- Implement `compute_next_due(rating: u8, consecutive_easy: u32) -> (chrono::DateTime<Utc>, u32)`:
  - Again (1): now (due immediately)
  - Hard (2): +1 day, reset `consecutive_easy = 0`
  - Good (3): +3 days, reset `consecutive_easy = 0`
  - Easy (4): interval = `7 * 2^min(consecutive_easy, 4)` days,
    `consecutive_easy += 1`

### SR3 — AI card generation
**Modify:** `mathmate-v2/src-tauri/src/flashcards.rs`

**Tasks:**
- `generate_cards(topic: &str, source_text: Option<&str>, model_config) -> Vec<(String, String)>`
- Prompt design:
  - System: "You are a math flashcard generator. Produce concise Q&A pairs."
  - Rules:
    - Front: a specific, unambiguous question or cloze statement
    - Back: the minimal correct answer; include LaTeX for formulas
    - Max 10 cards per call; prefer depth over breadth
    - No trivial vocabulary cards ("What is a matrix?" is too broad)
    - Prefer: definitions with precision, formula derivations, theorem
      conditions, worked example prompts ("What is det(A) if A = [[1,2],[3,4]]?")
  - If `source_text` is provided (from session): extract card candidates from
    the actual exchange rather than hallucinating
  - Output: JSON array of `{front: string, back: string}`
- Parse, deduplicate within deck, return

### SR9 — Memory DB integration (mastery signal)
**Modify:** `mathmate-v2/src-tauri/src/flashcards.rs`

**Tasks:**
- After `rate_flashcard`: find memory item(s) whose label matches the card's
  deck topic (loose text match) and update `memory_score` from the rating:
  - Again → `memory_score = max(0, current - 5)`  (no penalty below 0)
  - Hard → no change
  - Good → `memory_score = min(100, current + 5)`
  - Easy → `memory_score = min(100, current + 10)`
- This is a coarse signal; the evaluator agent produces the authoritative
  scores — flashcard ratings only nudge them

## 5) Content Quality Notes

**Good flashcard fronts for math:**
- "State the condition for a matrix to be invertible in terms of its determinant."
- "What does it mean geometrically when an eigenvector has eigenvalue λ = 1?"
- "Given f(x) = x³ - 3x, find the critical points."

**Bad fronts to avoid in the generation prompt:**
- "What is an eigenvalue?" (too vague)
- "Define integration." (too broad)
- "What chapter covers linear algebra?" (not conceptual)

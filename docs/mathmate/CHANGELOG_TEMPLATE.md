# Changelog Entry Template

Use this as a copy/paste starter for each new day/release in `CHANGELOG.md`.

```md
## YYYY-MM-DD

### Added
- 

### Changed
- 

### Fixed
- 

### Cleanup
- 

---
```

## Tips
- Keep bullets user-visible (what behavior changed).
- Group by outcome, not by file names.
- Keep entries short; link to dev logs for deep details.

## 60-second update checklist
1. Copy the template block into `CHANGELOG.md`.
2. Set today’s date (`YYYY-MM-DD`).
3. Add 1–3 bullets under **Added/Changed/Fixed** (skip empty sections if needed).
4. Add one **Cleanup** bullet if you removed debug code/logs or dead paths.
5. Ensure wording is user-facing (avoid file-level implementation detail).
6. Save and add a matching one-line note in the day’s dev log.

# Implementation Plan: Security — Study-Log Path Containment

## 1) Goal

Ensure `save_wrap_up` (and the future LLM-driven wrap-up described in the Mastery Evaluator roadmap item) cannot write outside the user's vault, and that every generated study-log file is clearly labeled as auto-generated.

Today, `src-tauri/src/wrapup.rs:110` writes to `<vault_path>/MathMate/Study Logs/YYYY/MM-Month/Study Log - YYYY-MM-DD.md`. The construction is reasonably safe — date components are not user-controlled — but `vault_path` is currently request-driven and `content` is fully LLM-controlled in the Phase 5 path. A future regression, or a malicious `vault_path` smuggled in via compromised renderer state, could land the file anywhere on disk.

This plan covers roadmap item **(8)**.

---

## 2) Threat Model (Practical)

- Adversary: prompt-injected model output that reaches `save_wrap_up` (or a model that simply emits a malicious "study log" once the Phase 5 evaluator lands).
- Capability sought: write arbitrary content to an arbitrary path on the user's disk (e.g., `~/.bashrc`, `~/.ssh/authorized_keys`).
- Mitigation: canonicalize `vault_path`, compute the target file path, then verify the target is inside the canonicalized vault before writing. Refuse otherwise.
- Out of scope: contents of the markdown file (those are still LLM-controlled; we mark them with a banner and trust the user's downstream tooling).

---

## 3) Scope

### In scope
- Refactor `save_wrap_up` to use a `pathscope` containment check.
- Add a header banner to every generated study log: `<!-- AUTO-GENERATED by MathMate — DO NOT EDIT — re-run /wrap-up to regenerate -->`.
- Add a front-matter block with timestamp, session id, and a sha256 of the input content (for audit / diff tools).
- Unit tests for the containment check + banner.
- Audit log entry: write a row to `~/.mathmate/audit.log` with timestamp, session id, vault path (canonical), and target file.

### Out of scope
- Replacing the LLM-driven wrap-up (covered by `Implementation_MasteryEvaluator.md`).
- Markdown sanitization in the wrap-up output (LLM content stays in the file; the file is plain markdown; Obsidian renders it without HTML by default).

## 4) System Design

### 4.1 Containment algorithm

```rust
fn ensure_inside_vault(vault_path: &str, target: &Path) -> Result<PathBuf, String> {
    let vault = std::fs::canonicalize(vault_path)
        .map_err(|e| format!("Could not canonicalize vault path '{}': {}", vault_path, e))?;

    // Target may not exist yet; canonicalize parent then re-join filename.
    let target_parent = target.parent().ok_or("Target has no parent")?;
    std::fs::create_dir_all(target_parent)
        .map_err(|e| format!("Could not create study log dir: {}", e))?;
    let canon_parent = std::fs::canonicalize(target_parent)
        .map_err(|e| format!("Could not canonicalize target parent: {}", e))?;
    let canon_target = canon_parent.join(target.file_name().ok_or("Target has no file name")?);

    if !canon_target.starts_with(&vault) {
        return Err(format!(
            "Refusing to write study log outside vault: target '{}' is not inside '{}'",
            canon_target.display(),
            vault.display()
        ));
    }
    Ok(canon_target)
}
```

Notes:
- Use canonicalized `PathBuf` values and `Path::starts_with` (component-aware) for containment checks.
- Avoid raw string prefix checks; they are easier to get wrong on `"/Users/x/Vault"` vs `"/Users/x/Vaultness"` cases.

### 4.2 Banner + front matter

The output `content` is rewritten as:

```md
<!-- AUTO-GENERATED by MathMate v2 on 2026-05-31T12:34:56Z — DO NOT EDIT — re-run /wrap-up to regenerate -->
<!-- session_id: <uuid> -->
<!-- content_sha256: <hex> -->

<original content here>
```

The hash is over the **incoming** `content` bytes, not the final file. This lets the user verify the file's provenance against `audit.log`.

### 4.3 Audit log

Append one line per `save_wrap_up` call to `~/.mathmate/audit.log`:

```
2026-05-31T12:34:56Z  wrapup  session=<uuid>  vault=<canonical>  target=<canonical>  bytes=<n>  sha256=<hex>
```

The file is rotated at 1 MB (rename to `audit.log.1`).

### 4.4 Refactor

`save_wrap_up` becomes:

```rust
pub fn save_wrap_up(project_id: &str, content: &str) -> Result<String, String> {
    let now = Utc::now();
    let vault_path = resolve_vault_path_from_project(project_id)?; // authoritative backend lookup
    let target = build_target_path(&vault_path, &now);
    let safe_target = pathscope::ensure_inside_vault(&vault_path, &target)?;
    let annotated = prepend_banner(content, &now);
    let hash = sha256_hex(content.as_bytes());

    std::fs::write(&safe_target, annotated.as_bytes())
        .map_err(|e| format!("Failed to write study log: {}", e))?;

    audit::log_wrapup(&now, /* session id from caller */, &vault_path, &safe_target, content.len(), &hash);

    Ok(safe_target.to_string_lossy().to_string())
}
```

(Phase 5 will pass a session id; for now, the signature change is a small, additive step.)
